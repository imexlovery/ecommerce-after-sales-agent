## Applicable-pattern interaction tests

The release suite must also test combined boundaries rather than only isolated units:

- a proposal becomes stale when a critical evidence hash or policy revision changes;
- the model recommends a ticket while the deterministic Evidence Gate denies it;
- an existing-ticket result changes after proposal but before confirmation;
- a crash occurs after the simulated write but before the local completion event, followed by
  read-back unavailability;
- cached evidence becomes invalid after source or authorization revision changes.

For each scenario the test must assert the canonical state owner, the rejected/fenced result, the
customer-visible response, the redacted event trail, and the allowed reconciliation action.
